# Space-Track

## 1. Подключение к источнику

- **Официальный сайт:** https://www.space-track.org/
- **Регистрация:** https://www.space-track.org/auth/createAccount
- **API:** https://www.space-track.org/basicspacedata/query/
- **Документация API:** https://www.space-track.org/documentation
- **Описание классов API:** https://www.space-track.org/documentation#/api-restRules
- **Правила использования:** https://www.space-track.org/documentation#/userAgreement

### 1.1. Авторизация

- Регистрация: обязательна.
- Авторизация: обязательна.
- Доступ предоставляется зарегистрированным пользователям после принятия пользовательского соглашения.
- Для API используются учётные данные Space-Track.
- Авторизация выполняется через HTTP-запрос с последующим использованием сессии.

### 1.2. Способ получения данных

- **Тип подключения:** REST API.
- **HTTP-метод:** GET для получения данных.
- **Авторизация:** через учётную запись и сессионную авторизацию.
- **Адрес запросов:** `/basicspacedata/query/`.
- **Основные параметры:** `class`, `NORAD_CAT_ID`, `OBJECT_ID`, `EPOCH`, `DECAY_DATE`, `CREATION_DATE`, `format`.
- **Форматы ответа:** JSON, CSV, XML, KVN, HTML, TLE, 3LE.

Пример запроса:

```text
https://www.space-track.org/basicspacedata/query/class/gp/NORAD_CAT_ID/25544/format/json
```

## 2. Доступные данные

### 2.1. Основные наборы данных

| Класс API | Название | Краткое описание |
|---|---|---|
| `GP` | General Perturbations | Актуальные орбитальные элементы объектов |
| `GP_HISTORY` | General Perturbations History | Исторические версии орбитальных элементов |
| `SATCAT` | Satellite Catalog | Каталог космических объектов |
| `SATCAT_DEBUT` | Satellite Catalog Debut | Новые объекты, добавленные в каталог |
| `DECAY` | Decay | История схода объектов с орбиты |
| `TIP` | Tracking and Impact Prediction | Сообщения о прогнозируемом сходе объектов |

Дополнительные наборы:

| Класс API | Название | Краткое описание |
|---|---|---|
| `CDM` | Conjunction Data Message | Сообщения о сближениях космических объектов |
| `BOX_SCORE` | Box Score | Статистика объектов, находившихся на орбите |
| `60_DAY_DECAY` | 60-Day Decay | Прогнозы схода объектов с орбиты на горизонте 60 дней |

Доступность отдельных наборов может зависеть от прав учётной записи.

### 2.2. Форматы данных

| Формат | Описание |
|---|---|
| JSON | Структурированные данные |
| CSV | Табличный формат |
| XML | CCSDS OMM XML |
| KVN | CCSDS OMM KVN |
| HTML | Представление данных в HTML |
| TLE | Двухстрочные элементы орбиты |
| 3LE | TLE с названием объекта |

Для новых объектов рекомендуется использовать JSON, CSV, XML или KVN. Форматы TLE и 3LE имеют ограничения по номеру объекта.

## 3. Ограничения

### 3.1. Ограничения частоты запросов

Общее ограничение API:
- Менее 30 запросов в минуту.
- Менее 300 запросов в час.

Ограничения для отдельных наборов:

| Набор | Допустимая частота | Особенности |
|---|---|---|
| `GP` | 1 раз в час | Для актуальных орбитальных данных |
| `GP_HISTORY` | 1 раз за весь период использования для конкретной истории объекта | После загрузки историю необходимо хранить локально |
| `SATCAT` | 1 раз в день | После 17:00 UTC |
| `SATCAT_DEBUT` | 1 раз в день | После 17:00 UTC |
| `DECAY` | 1 раз в день | Полученную историю необходимо хранить локально |
| `TIP` | 1 раз в час | Для отдельных объектов при сходе в ближайшие 12 часов допускается запрос раз в 10 минут |
| `CDM` | 3 раза в день | Для всех сообщений; для конкретного события — 1 раз в час |
| `BOX_SCORE` | 1 раз в день | После 17:00 UTC |
| `60_DAY_DECAY` | 1 раз в неделю | По средам после 17:00 UTC |

### 3.2. Особенности получения данных

- Не следует отправлять отдельный запрос для каждого спутника. Для нескольких объектов необходимо объединять идентификаторы в одном запросе.
- Не следует повторно загружать уже полученную историю `GP_HISTORY`.
- Для получения актуальных орбитальных данных необходимо использовать `GP`, а не `GP_HISTORY`.
- Для больших исторических выборок рекомендуется использовать подготовленные архивы, если они подходят для задачи.
- При разработке и тестировании необходимо учитывать ограничения производственного API.

### 3.3. Ограничения доступа

- Требуется действующая учётная запись.
- Space-Track может ограничивать объём и продолжительность доступа.
- Нарушение правил использования API может привести к временной или постоянной блокировке учётной записи.
- Нельзя использовать несколько учётных записей для обхода ограничений.
- Необходимо соблюдать пользовательское соглашение и условия распространения данных.
