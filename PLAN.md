## Этап 4. Организация хранилища данных

**Цель:** организовать хранение Bronze и Silver в S3 с тремя ролями
хранилищ и вести метаданные в PostgreSQL.

- **RustFS** — основное S3-хранилище, в него пишут загрузчик и обработка.
- **MinIO** — локальный дубль Bronze и Silver, запускается без Docker.
- **Yandex Object Storage** — внешний бэкап в пределах бесплатного уровня.
- **Gold** в S3 не хранится: витрины живут в ClickHouse (этап 6).

## Критерии завершения проекта

Платформа считается реализованной, когда она:

- получает данные из нескольких независимых источников;
- сохраняет оригиналы и историю обновлений;
- хранит Bronze и Silver в S3 (RustFS), дублирует их в MinIO и выгружает бэкап во внешнее облако;
- использует PostgreSQL для метаданных и управления загрузками;
- выполняет нормализацию, проверку качества и сопоставление данных;
- строит аналитические витрины Gold в ClickHouse через dbt;
- использует DuckDB для локальной проверки данных;
- автоматически запускает конвейеры данных через Airflow;
- выполняет орбитальные расчёты через SGP4;
- предоставляет данные через FastAPI;
- контролирует качество, актуальность данных и копий, состояние процессов.

## Принципы разработки

1. Каждый подэтап должен завершаться работающим результатом.
2. Перед внедрением новой технологии необходимо разобраться в её назначении.
3. Для каждого этапа предусматриваются тесты и краткая техническая
   документация.
4. Исходные данные Bronze не изменяются: обработанные наборы формируются
   независимо.
5. Архитектура развивается постепенно, без преждевременного усложнения.
6. В S3 хранятся только Bronze и Silver, Gold живёт в ClickHouse.
7. Данные удаляются только по политике хранения: последний снимок набора
   не удаляется, копирование между хранилищами ничего не удаляет.
