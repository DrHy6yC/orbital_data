Этап 3. Реализация сбора исходных данных
Основные технические принципы
Чтобы не усложнять реализацию, предлагаю зафиксировать следующие ограничения.

1. Обработка ошибок

Обрабатываем только ситуации, которые могут нарушить загрузку или привести к ограничению доступа:
- тайм-аут соединения;
- временная недоступность источника;
- HTTP 429 — превышение допустимой частоты запросов;
- HTTP 5xx — временные ошибки сервера;
- ошибки авторизации и HTTP 403 — прекращение дальнейших запросов при отсутствии доступа.
Не делаем сложную систему обработки исключений и многоуровневые механизмы восстановления.

2. Защита от блокировок
- Соблюдаем ограничения частоты запросов источника.
- Не отправляем параллельно большое количество запросов.
- При HTTP 429 учитываем Retry-After, если он предоставлен.
- Не повторяем запросы бесконечно.
- Не пытаемся обходить ограничения источников.
3. Хранение данных

На первом этапе используем один общий каталог:
data/
├── celestrak/
│   ├── ...
│   └── ...
│
└── space_track/
    ├── ...
    └── ...


Форматы оригинальных ответов сохраняем без преобразования. Если источник возвращает JSON — сохраняем JSON, если CSV — CSV.

4. Проверки

Только необходимые:
- запрос выполнен успешно;
- ответ получен;
- файл сохранён;
- сохранённый файл не пустой.
Не внедряем пока контроль качества данных, сравнение наборов, проверку бизнес-правил и сложную проверку целостности.
