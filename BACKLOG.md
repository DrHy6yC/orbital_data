1.11. Проверить `uv run ruff check .` и `uv run pytest -q`.

**Живая проверка**

- `--dry-run` печатает по одному ключу на набор, в RustFS ничего
  не меняется.
- Удалить в RustFS один объект, например
  `celestrak/gp_stations/2026-11-17T14-54-50Z.json`.
- `--dataset celestrak/gp_stations` без `--dry-run`: объект
  восстановлен, размер и `sha256` совпали.
- Повторный прогон: «уже на месте», счётчик скопированных ноль.
- `utils/check_s3.py --list` показывает ключ; `select` по
  `snapshot_copies` показывает строку `rustfs`.

**Решения, принятые при планировании**

- `--dataset` одним значением `источник/набор`: повторяет путь
  в бакете и не допускает неверной пары.
- Общий код работы с облаком живёт в пакете, а не дублируется
  в двух скриптах; `check_backup_restore.py` и
  `restore_from_cloud.py` пользуются им.
- Отметки `rustfs` пишутся отдельной функцией `ensure_primary_copy`:
  `save_copy_for_key` создаёт только строки других хранилищ.
- Дампы PostgreSQL скрипт не восстанавливает: без `snapshots`
  не с чем связать строки копий.
