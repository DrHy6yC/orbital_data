## Этап 2. Подэтап 2.1. Исследование CelesTrak

### 1. Изучить разделы сайта CelesTrak (шаг 1)
- Файл и место: `docs/research/celestrak/celestrak_research.md`,
  раздел «1. Общий обзор сайта» и разделы 2-5 по источникам
- Что нужно сделать: разобрать разделы Current Data, Supplemental GP Data,
  SATCAT и GPE Statistics: назначение, состав данных, польза для платформы.
- Ожидаемый результат: по каждому разделу записаны назначение и состав
  данных.
- Как проверить: по записям понятно, какие данные нужны платформе и в каком
  разделе источника они лежат.

### 2. Исследовать группы космических объектов (шаг 2)
- Файл и место: `docs/research/celestrak/celestrak_research.md`, раздел
  «7. Группы объектов»
- Что нужно сделать: для групп ACTIVE, STATIONS, STARLINK, ONEWEB, GPS-OPS,
  GLONASS-OPS, GALILEO, WEATHER, CUBESAT, DEBRIS выяснить состав, количество
  объектов, доступные сведения, частоту обновления, пересечения между
  группами и возможность запроса по одному объекту.
- Ожидаемый результат: таблица групп с количеством объектов и пометкой
  о пересечениях.
- Как проверить: в таблице присутствуют все десять групп, по каждой
  заполнены все колонки.

### 3. Исследовать API и параметры запросов (шаг 3)
- Файл и место: `docs/research/celestrak/celestrak_research.md`,
  разделы «2.3. Параметры запроса», «3.2. Запросы SupGP»,
  «4.2. Способы получения»
- Что нужно сделать: разобрать адрес gp.php с параметрами CATNR, INTDES,
  GROUP, NAME, SPECIAL, FORMAT, а также satcat/records.php; выписать примеры
  запросов.
- Ожидаемый результат: описание параметров API и готовые примеры адресов.
- Как проверить: по описанию можно составить запрос, не открывая
  документацию источника.

### 4. Исследовать форматы данных (шаг 4)
- Файл и место: `docs/research/celestrak/celestrak_research.md`, раздел
  «2.5. Форматы»
- Что нужно сделать: сравнить JSON, CSV, XML, KVN, TLE/3LE и 2LE по составу
  полей и пригодности для обработки; проверить ограничение TLE на длину
  каталожного номера и подтвердить выбор JSON с данными OMM.
- Ожидаемый результат: таблица форматов и обоснованный вывод о формате
  по умолчанию.
- Как проверить: вывод опирается на реальные ответы API, а не на
  предположения.

### 5. Изучить правила использования API (шаг 5)
- Файл и место: `docs/research/celestrak/celestrak_research.md`, раздел
  «6. Правила использования»
- Что нужно сделать: зафиксировать периодичность обновления GP-данных,
  ограничения на частоту запросов, поведение при повторном скачивании
  неизменившихся данных, HTTP-коды ошибок, пустой ответ и поведение при
  недоступности источника.
- Ожидаемый результат: раздел с проверенными фактами без предположений.
- Как проверить: по разделу можно выбрать частоту загрузки без риска
  блокировки со стороны источника.
