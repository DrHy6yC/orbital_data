# Активные задачи

Список незакрытых задач проекта. Выполненная задача удаляется из файла.
Глобальные этапы и их результаты описаны в `PLAN.md`.

## Этап 1. Подготовка проекта

### 1.7. Дополнить README.md
- Файл и место: `README.md`
- Что нужно сделать: добавить разделы «Источники данных» и «Структура проекта»,
  убрать из описания структуры служебные файлы.
- Ожидаемый результат: из README понятно, что делает платформа, как её
  запустить и из чего состоит проект.
- Как проверить: пройти раздел «Быстрый запуск»: `uv sync`, затем `uv run pytest`.

### 1.8. Исключить локальные файлы из Git
- Файл и место: `.gitignore`
- Что нужно сделать: добавить `AGENTS.md` в список игнорируемых файлов,
  чтобы локальные рабочие правила не попадали в репозиторий.
- Ожидаемый результат: `AGENTS.md` остаётся на диске, но `git status`
  его не показывает.
- Как проверить: `git status --ignored` содержит строку `!! AGENTS.md`.

### 1.9. Переименовать файл задач
- Файл и место: `YOUR_PARTS.md` → `BACKLOG.md`
- Что нужно сделать: переименовать файл, обновить ссылки в `README.md`
  и в настройках рабочих инструментов.
- Ожидаемый результат: файл называется `BACKLOG.md`, ссылок на старое
  имя не осталось.
- Как проверить: `Get-ChildItem *.md` показывает `BACKLOG.md`, а поиск
  по тексту `YOUR_PARTS` ничего не находит.

### 1.10. Сделать первые коммиты
- Файл и место: репозиторий Git, ветка `main`
- Что нужно сделать: разделить текущие изменения на пять коммитов по типам
  и оформить каждый по `COMMIT_RULES.md`. Текст коммита готовится
  в `COMMIT_MSG.txt`.
- Ожидаемый результат: в истории пять коммитов, каждый про одно изменение.
- Как проверить: `git log --oneline` показывает пять строк,
  `git status` — «nothing to commit».

### 1.11. Проверить этап
- Файл и место: весь проект
- Что нужно сделать: запустить тесты и проверить состояние репозитория.
- Ожидаемый результат: тест проходит, рабочая директория чистая.
- Как проверить: `uv run pytest` выдаёт `1 passed`, `git status` пуст.
